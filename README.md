# DeepSeek Browser Bridge

Локальный сервис для обмена запросами между AI-агентом и тестовым чатом в Google Chrome на macOS. Запросы и результаты хранятся в SQLite. Расширение Manifest V3 получает задания через Chrome Native Messaging. Bridge слушает только `127.0.0.1:8765`.

## Установка

Требуются macOS, Google Chrome 120+ и Python 3.12+. Один раз откройте отдельный постоянный профиль обычного Chrome.

```sh
open -na "Google Chrome" --args \
  --user-data-dir="$HOME/Library/Application Support/DeepSeekBridgeChrome"
```

1. В этом профиле откройте `chrome://extensions`. Включите режим разработчика, нажмите **Загрузить распакованное расширение** и выберите каталог `chrome-extension` из проекта.
2. Скопируйте ID расширения. Запустите `./install.sh ID_РАСШИРЕНИЯ` из корня проекта. Для запуска Bridge при входе в macOS добавьте `--launch-agent`. Переменная `PYTHON_BIN` позволяет выбрать интерпретатор при создании окружения.
3. При установке без LaunchAgent запустите `.venv/bin/python -m bridge.main`. Если Bridge уже запущен вручную, остановите его перед загрузкой LaunchAgent.
4. Откройте [тестовый чат](http://127.0.0.1:8765/mock/) в выделенном профиле. Можно оставить вкладку в фоне. Всплывающее окно расширения покажет, доступен ли чат.
5. Откройте [панель управления](http://127.0.0.1:8765/). Введите локальный токен из `~/Library/Application Support/DeepSeekBridge/token`. Панель держит введённый токен в памяти до перезагрузки страницы.

Каталог состояния можно переопределить переменной `DEEPSEEK_BRIDGE_STATE` при установке и при ручном запуске Bridge. Каталог должен иметь права `700`. Токен создаётся с правами `600`. Журналы LaunchAgent находятся в этом же каталоге и содержат идентификаторы и переходы состояний заданий. Тексты запросов и ответов сохраняются в базе. Тестовый чат хранит историю в данных выделенного профиля Chrome.

Установщик сохраняет манифест в `NativeMessagingHosts` внутри каталога, переданного Chrome в `--user-data-dir`. Для другого каталога задайте `DEEPSEEK_BRIDGE_CHROME_DATA` при запуске установщика. Манифест разрешает только ID распакованного расширения, указанный при установке. Если ID изменился после перемещения проекта, повторите установку с новым ID. [Документация Chrome](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)

## Запрос из Python

```python
import asyncio

from bridge.client import bridge


async def main():
    response = await bridge.ask(provider="deepseek", prompt="Первая строка\nВторая строка")
    print(response.status, response.answer)
    if response.status == "succeeded":
        follow_up = await bridge.ask(
            provider="deepseek",
            prompt="Продолжи диалог",
            conversation_id=response.conversation_id,
        )
        print(follow_up.answer)


asyncio.run(main())
```

Без `conversation_id` клиент создаёт новый диалог. С ним он продолжает ранее успешно созданный диалог. Выделенный профиль хранит соответствие между идентификаторами Bridge и тестового чата.

## HTTP API

`GET /health` отвечает без авторизации. Для остальных запросов передайте заголовок `Authorization: Bearer <токен>`.

| Метод и путь | Назначение |
| --- | --- |
| `POST /v1/tasks` | Создать задание. Поля `provider`, `prompt`, `mode` и `conversation_id`. |
| `GET /v1/tasks/{id}` | Состояние и метаданные задания. |
| `GET /v1/tasks/{id}/result` | Состояние, ответ, Markdown при наличии и код ошибки. |
| `POST /v1/tasks/{id}/cancel` | Отменить задание. |
| `POST /v1/tasks/{id}/resume` | Возобновить задание, приостановленное до отправки. |
| `GET /v1/overview` | Подключение браузера, очередь и история. |
| `POST /v1/processing/{start,pause,resume}` | Управлять выдачей новых заданий. |

Пример запроса через `curl` без передачи токена в аргументах процесса.

```sh
printf 'Authorization: Bearer %s\n' "$(cat "$HOME/Library/Application Support/DeepSeekBridge/token")" |
  curl -fsS http://127.0.0.1:8765/v1/tasks -H @- \
    -H 'Content-Type: application/json' \
    -d '{"provider":"deepseek","prompt":"Проверка","mode":"NEW_CHAT"}'
```

## Сбои и восстановление

Bridge выдаёт одно задание за раз. Отсчёт времени задания начинается при первой выдаче расширению. До подтверждения начала отправки аренда может истечь, и задание вернётся в очередь с ограничением попыток и времени. После подтверждения Bridge помечает потерянную связь как `uncertain`, чтобы исключить автоматическую повторную отправку. После перезапуска Bridge продолжает обрабатывать сохранённую очередь. Расширение восстанавливает канал после обрыва. После закрытия Chrome нужно снова открыть выделенный профиль с вкладкой чата.

Если тестовый чат требует входа или ручной проверки, задание получит `paused`. После устранения причины возобновите его через панель. Отмена активного задания передаётся расширению при ближайшей проверке связи. Пауза обработки удерживает следующие задания в очереди. В тестовом чате переключатель **Сценарий** позволяет воспроизвести ошибки, прерывание потока и изменение DOM. Вкладку с имитацией изменения DOM нужно перезагрузить после проверки.

## Реальный DeepSeek

Для веб-чата используется `provider="deepseek"`. После обновления перезапустите Bridge, перезагрузите распакованное расширение и обновите вкладку DeepSeek. Оставьте в выделенном профиле одну вкладку `chat.deepseek.com` с выполненным вручную входом. Новый диалог открывается в этой вкладке. Продолжение использует `conversation_id` из успешного ответа Bridge.

После подтверждения разрешения в `config.yaml` включён `deepseek_browser_enabled`. Значение `false` блокирует выдачу и создание заданий для реального провайдера. Селекторы в `chrome-extension/adapters/live-selectors.js` основаны на записи DOM. Адаптер извлекает видимый текст ответа и требует совпадения запроса, состояния генерации и признака её завершения.

Для проверки используйте пример Python выше. Для прямого подключения агента доступен [официальный DeepSeek API](https://api-docs.deepseek.com/).

### Запись структуры интерфейса DeepSeek

1. Перезагрузите распакованное расширение на странице `chrome://extensions` в выделенном профиле.
2. В пустом чате DeepSeek откройте меню расширения. Разверните **Диагностика DeepSeek** и нажмите **Начать запись DOM**.
3. Вручную отправьте «Ответь одним словом: тест». Когда появится полный ответ, снова откройте меню и нажмите **Скачать отчёт JSON**.

Запись длится до 60 секунд. В отчёт попадают структура элементов, разрешённые подписи кнопок и изменения во время ответа. Текст запросов и ответов, значения полей, cookies и идентификаторы диалогов в отчёт не включаются. Файл `deepseek-dom.json` сохраняется локально.

## Тестирование

Для интеграционного теста требуется Node.js 22+.

```sh
npm ci
node --test tests/live-adapter.cjs
.venv/bin/python -m pytest -q
```

Интеграционный тест запускает Bridge на штатном порту 8765 и отдельный Native Messaging Host. Перед запуском освободите этот порт. Тест использует временный каталог состояния, DOM из поставляемой страницы и имитацию браузерных API расширения.

Для проверки в обычном Chrome выполните шаги установки, оставьте тестовый чат открытым, запустите пример Python и проверьте в панели оба ответа. Во время прогона можно работать в другом приложении. Для проверки восстановления перезапустите Bridge, затем Chrome с тем же профилем и повторите запрос с сохранённым `conversation_id`.
